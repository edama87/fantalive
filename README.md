# FantaLive Bundlesliga

Live fantacalcio head-to-head app per la lega privata Bundlesliga. Mostra risultati in tempo reale delle sfide fantasy, calcola i punteggi secondo il regolamento ufficiale e gestisce il mercato settimanale.

## Stack

- **Frontend**: Next.js 16 (App Router) + TypeScript + Tailwind CSS
- **Hosting**: Vercel
- **Database**: Supabase (PostgreSQL + Realtime)
- **Live Data**: ESPN API (con fallback Mock per development)

## Quick Start


### 5. Configure Live Ingestion (pg_cron)

Live data ingestion runs every minute via **Supabase pg_cron + pg_net** (not Vercel Cron, which only supports daily schedules on Hobby plan).

#### Setup Vault Secrets

Before applying `00006_live_cron.sql`, add these secrets in Supabase Dashboard > Project Settings > Vault:

| Secret Name | Value |
|-------------|-------|
| `fantalive_app_url` | Your Vercel app URL, e.g. `https://fantalive.vercel.app` |
| `fantalive_cron_secret` | Same value as `CRON_SECRET` env var in Vercel |

```sql
-- Or via SQL:
SELECT vault.create_secret('https://fantalive.vercel.app', 'fantalive_app_url');
SELECT vault.create_secret('your-cron-secret-here', 'fantalive_cron_secret');
```

#### How it Works

1. pg_cron schedules the `fantalive-live` job every minute
2. pg_net makes an HTTP GET to `/api/cron/live` with `Authorization: Bearer <secret>`
3. The endpoint performs a **cheap early-exit** if no Serie A match is:
   - Currently live or at halftime
   - Within -15 minutes (pre-kickoff) to +150 minutes (post-kickoff) of scheduled time
4. Only when matches are in the active window does it fetch from ESPN and write to DB

This ensures minimal resource usage outside match windows while maintaining minute-level updates during live matches.

#### Verify the Cron Job

```sql
-- List scheduled jobs
SELECT * FROM cron.job;

-- Check recent job runs
SELECT * FROM cron.job_run_details ORDER BY start_time DESC LIMIT 10;
```

## Scoring Rules

### Bonus/Malus
| Event | Points |
|-------|--------|
| Goal | +3 |
| Penalty scored | +2 |
| Penalty missed | -3 |
| Penalty saved (GK) | +3 |
| Assist | +1 |
| Own goal | -1 |
| Yellow card | -0.5 |
| Red card | -1 |
| Goal conceded (GK) | -1 |
| Home bonus | +2 |

### Goal Thresholds
66 → 1 | 72 → 2 | 77 → 3 | 81 → 4 | 85 → 5 | +4 per additional

### Modifiers
- **Defense**: Average defender votes → opponent bonus/malus
- **Midfield**: Total comparison → winner gets bonus, loser malus
- **Attack**: High-rated forwards who don't score → bonus

## ESPN Provider

The ESPN provider fetches live Serie A data from:
- Scoreboard: `site.api.espn.com/apis/site/v2/sports/soccer/ita.1/scoreboard`
- Summary: `site.api.espn.com/apis/site/v2/sports/soccer/ita.1/summary?event={id}`

### Vote Estimation Heuristic
ESPN doesn't provide player ratings, so we estimate votes:

- Base: 6.0 (≥45 min) or 5.5 (<45 min)
- Goal: +1.0
- Penalty scored: +0.5
- Assist: +0.5
- Own goal: -1.0
- Penalty missed: -1.5
- Yellow card: -0.5
- Red card: -1.0

Votes are marked as "stimato" until reconciled with official votes via CSV.

### Player Matching
Players are matched using:
1. Normalized name lookup
2. Last name matching
3. Manual alias table (in DB and code)
4. Fuzzy substring matching

## Market Management

### Rules
- Window: Monday 00:00 - Thursday 18:59 (closed in January)
- Initial credits: 60 per team
- Loan: Fixed 10 credits
- Release (Serie A player): No refund
- Release (left Serie A): Configurable

### Email Import (/admin/mercato)
1. Paste FMS Revo market email
2. Auto-parse with fuzzy matching
3. Review/edit transactions
4. Validate (credits, slots, duplicates)
5. Confirm to apply

## Lineup Import

### FMS Revo Integration (/admin/formazioni)

Import team lineups from the FMS Revo platform for each fantasy round.

**Setup:**
1. Set `FMSREVO_USERNAME` and `FMSREVO_PASSWORD` in Vercel environment variables
2. These credentials are server-only and never exposed to the client

**Automatic Fetch:**
1. Go to /admin/formazioni
2. Select the fantasy round to import
3. Click "Scarica da FMS Revo"
4. The server logs into FMS Revo, fetches the lineup page for the corresponding Serie A matchday
5. Review matched lineups, fix any unmatched players
6. Confirm to save

**Manual Paste (fallback):**
1. Copy the content from the FMS Revo lineup page
2. Paste into the textarea
3. Parse and review as above

**Player Matching:**
- Names are matched using fuzzy matching (SURNAME First format)
- Role hints (POR/DIF/CEN/ATT) improve matching accuracy
- Unmatched players are highlighted for manual correction

**Missing Lineups:**
- Teams without a submitted lineup are flagged
- Option to use previous round's lineup as fallback (configurable)

## Supabase Schema

### Core Tables
```sql
teams              -- 10 fantasy teams
players            -- Serie A players (250+)
player_aliases     -- Name mappings for ESPN
roster_versions    -- Point-in-time roster snapshots
roster_players     -- Players in each version
market_transactions -- Transaction history
rounds             -- 27 rounds with pairings
match_pairings     -- Head-to-head matches
```

### Live Data Tables
```sql
serie_a_matches    -- Real match state
live_events        -- Goals, cards, etc.
live_votes         -- Estimated votes
official_votes     -- Final votes (CSV import)
```

### RLS Policies
- All tables: Public read
- Writes: Server-side only (via service role)
- Admin routes protected by ADMIN_PASSWORD

## Development

### Local Database
Set `NEXT_PUBLIC_USE_LOCAL_DB=true` to use in-memory database with localStorage persistence.

### Mock Provider
Set `LIVE_PROVIDER=mock` for simulated match data (deterministic, seeded random).

### Adding a New Provider
1. Create `src/providers/your-provider.ts` implementing `LiveDataProvider`
2. Add to factory switch in `src/providers/factory.ts`
3. Run contract tests to verify compliance
